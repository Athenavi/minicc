# 三方登录 + 手机验证码登录 设计方案

> 版本 v1 · 2026-08-21 · 基于代码库实况（上游基线 ce25332 + 本地 1eeaa2f）
> 决策：① 1 账号绑 N 三方身份 ② Provider 全量（微信/GitHub/Google/钉钉/飞书/QQ + 自定义 OIDC）③ 含手机验证码登录

---

## 0. 现状盘点（重要：上游已埋好半套设施）

| 已存在 | 位置 | 状态 |
|---|---|---|
| OIDC Provider 配置表 | `ent_oidc_providers`（migrations/20260922000002） | 已迁移，未使用 |
| 外部身份绑定表 | `ent_user_identities`，UNIQUE(provider_id, subject) | 已迁移，未使用 |
| SSO 完整流程处理器 | `internal/api/sso_handler.go`（681 行：公开登录/回调 + 管理 CRUD） | **未挂载路由**（注释"供 Phase 7 集成任务调用"） |
| OIDC 交换器 + state HMAC | `internal/auth/oidc.go`（go-oidc 发现/换 token/验 nonce） | 仅标准 OIDC |

**环境**：Go 1.26.6 已可用（此前"无 Go 工具链"结论过时），Go 侧可本地编译验证。

## 1. 总体架构

```
前端                          Go 网关 (:8080)                        存储
────────────────────────     ────────────────────────────────     ─────────────
LoginView   ─┐               SSOHandler(扩展)
RegisterView ─┼─ provider ──▶  ├─ OIDC 路径   → go-oidc 发现/换token ──▶ PG
ProfileView(绑定卡片)          ├─ OAuth2 路径 → oauth_profiles 模板     ent_oidc_providers(扩展)
admin/OAuthProvidersView ─┘   ├─ bind/login 双模式 state              ent_user_identities
LoginView(验证码Tab) ──────▶  SMSHandler(新) → 阿里云/腾讯云 SMS ──▶ Redis: sms:code:{phone}
                              ↓ 签发 JWT(复用 auth.Authenticator)      users(+phone,+password_set)
```

原则：**复用现有 SSOHandler 骨架**（state 编解码/加密/自动建号/角色映射全部保留），只做扩展不重写。

## 2. 数据模型

### 2.1 迁移 `20260822000001_oauth_login.up/down.sql`

```sql
-- Provider 配置表扩展：支持 OAuth2 协议与预设模板
ALTER TABLE ent_oidc_providers
  ADD COLUMN protocol      VARCHAR(16)  NOT NULL DEFAULT 'oidc',   -- 'oidc' | 'oauth2'
  ADD COLUMN provider_type VARCHAR(32)  NOT NULL DEFAULT 'custom', -- google/github/wechat/dingtalk/feishu/qq/custom
  ADD COLUMN display_name  VARCHAR(64),
  ADD COLUMN icon          VARCHAR(64),                            -- 前端内置图标 key
  ADD COLUMN sort_order    INT         NOT NULL DEFAULT 100,
  ADD COLUMN auth_url      VARCHAR(512),                           -- oauth2 端点覆盖（模板缺省可自动填充）
  ADD COLUMN token_url     VARCHAR(512),
  ADD COLUMN userinfo_url  VARCHAR(512),
  ADD COLUMN extra         JSONB       NOT NULL DEFAULT '{}';      -- provider 特有项（微信 mode=open|mp、unionid 策略等）

-- 手机号：资料字段 + 验证码登录标识
ALTER TABLE users
  ADD COLUMN phone        VARCHAR(32),
  ADD COLUMN password_set BOOLEAN     NOT NULL DEFAULT TRUE;      -- SSO 自动建号写 FALSE（随机 bcrypt 不可登录）
CREATE UNIQUE INDEX uq_users_tenant_phone ON users(tenant_id, phone) WHERE phone IS NOT NULL;

-- 已有 ent_user_identities 不动：UNIQUE(provider_id, subject) 即
-- "一个三方账号全局只能绑一个本地账号"；user_id 无唯一约束 → 1 账号绑 N 三方身份 ✓
```

**双轨约定**：Python 侧 `python-engine/app/db.py ensure_tables` 同步补列（幂等 ALTER）。

## 3. Provider 模板注册表（Go，新文件 `internal/auth/oauth_profiles.go`）

```go
type ProviderProfile struct {
    Type        string            // google/github/wechat/dingtalk/feishu/qq
    Protocol    string            // oidc | oauth2
    Issuer      string            // oidc 用
    AuthURL, TokenURL, UserinfoURL string   // oauth2 用
    Scopes      []string
    Extra       map[string]any
    // IdentityFetch: provider 特有的"token → 身份"抽取逻辑（注入到 exchanger）
}
```

| Provider | 协议 | 关键端点（实现时以官方文档为准 WebFetch 校验） | subject 取值 | 特殊点 |
|---|---|---|---|---|
| Google | OIDC | issuer `https://accounts.google.com` | sub | 复用现有 go-oidc 路径，零新代码 |
| GitHub | OAuth2 | `github.com/login/oauth/authorize` / `access_token`（Accept: JSON）/ `api.github.com/user`（邮箱为空再查 `/user/emails`） | id | token 响应需 JSON Accept 头 |
| 微信 | OAuth2 | 开放平台扫码 `open.weixin.qq.com/connect/qrconnect`（extra.mode=open）/ 公众号网页授权（mode=mp）；token `api.weixin.qq.com/sns/oauth2/access_token`；userinfo `sns/userinfo` | **unionid 优先，openid 兜底** | appid/secret 走 query 参数；需企业资质 |
| 钉钉 | OAuth2 | `login.dingtalk.com/oauth2/auth` → `api.dingtalk.com/v1.0/oauth2/userAccessToken` → `contact/users/me` | unionId | 新版 v1.0 接口 |
| 飞书 | OAuth2 | `passport.feishu.cn/suite/passport/oauth/v2/authorize` → `/token` → `/userinfo` | user_id / open_id | app_access_token 体系 |
| QQ | OAuth2 | `graph.qq.com/oauth2.0/authorize` → `/token`（jsonp→JSON）→ `/oauth2.0/me` 取 openid + `/user/get_user_info` | openid | 需审核资质 |
| custom | OIDC | 管理员填 issuer | sub | 任意标准 OIDC（Keycloak/Auth0/Okta/Authing…） |

**Exchanger 抽象泛化**：现有 `OIDCExchanger` 接口扩展为

```go
type ExternalIdentity struct { Subject, Email, Name, AvatarURL string; Extra map[string]string }
type ProviderExchanger interface {
    AuthURL(ctx, cfg, state, nonce) (string, error)
    Exchange(ctx, cfg, code) (*ExternalIdentity, error)  // OIDC 内部保留 nonce 校验
}
```

`oidc.go` 现有实现适配；新增 `oauth2_exchanger.go` 按 profile 分派各 provider 的 userinfo 抽取。

## 5. 绑定流程（state 双模式）

`StatePayload` 扩展：`{provider_id, nonce, exp, mode: 'login'|'bind', uid}`（HMAC 覆盖全部字段，兼容旧格式）。

```
绑定：登录态下前端跳转 GET /v1/auth/sso/login/{id}?mode=bind
      → 后端从 JWT cookie 取 uid 写入 state → 302 到三方授权页
      → callback 验 state：
          mode=bind → 校验当前会话 uid 与 state.uid 一致
                    → 该三方身份已绑定他人？→ 409 冲突页（带"前往登录"引导）
                    → 否则 INSERT ent_user_identities → 302 /profile?bind=ok
          mode=login → 现有逻辑（查绑定 → 未绑定按 auto_provision 建号/拒绝 → 签发 JWT）
```

自动建号增强：`provisionAndBind` 写 `password_set=false`；id_token/userinfo 带手机号（微信/钉钉可能返回）时回填 `users.phone`。

## 7. 安全设计

1. **沿用**：state HMAC+10min TTL 防重放、client_secret AES-GCM 加密入库、bcrypt、JWT HttpOnly+SameSite=Lax cookie、登录失败审计
2. **短信**：验证码 5min TTL + 5 次错误作废；60s 冷却；单号日限 10 条；手机号格式校验（+86 11 位）；验证码登录写审计
3. **绑定**：UNIQUE(provider_id, subject) 数据库兜底并发冲突 → 409；解绑守卫保证至少一种可用登录方式；bind 模式必须同时持有有效 state 和有效会话
4. **微信 unionid 作 subject**：同主体多 app 不产生重复身份
5. **管理面**：secret 永不回显（masked）；SMS AK/SK 同等加密
6. **fail-loud**：SMS 服务商未配置 → 发送接口 503 显式报错；provider 模板缺失 → 400 而非静默降级

## 9. 风险与边界

- **微信/QQ 需企业资质**：本地无凭据，真实接口联调依赖用户提供 appid/secret；代码层用 fake exchanger 全覆盖单测
- **钉钉/飞书接口版本**：表中端点基于 2026-09 已知 v1.0/v2 接口，实现时逐个 WebFetch 官方文档校验
- **redirect_uri 依赖 `MINICC_PUBLIC_BASE_URL`**：本地 localhost 回调需在 provider 后台登记
- **Go 模块依赖**：`go-oidc`/`oauth2` 已在 go.mod；阿里云/腾讯云 SMS 需新增 SDK 或直接 HTTP 调用（倾向轻量 HTTP，避免引入大 SDK）
- **上游合并**：本设计全部为增量（ALTER + 新文件 + 扩展现有 handler），与上游冲突面小
